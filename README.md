괴물 손님이 찾아와 두루뭉술한 주문을 남깁니다 — *"바다 느낌 나게 해줘"*, *"블루베리 케이크! 쪽지는 필요없어요"*.
정답은 손님 머릿속에만 있습니다. 플레이어는 **채팅으로 질문**해 단서를 좁히고, 시트를 굽고 색과
토핑을 올려 케이크를 냅니다. 손님의 만족도만큼 코인이 쌓이죠.

<p align="center"><em>"애매함을 읽어내는 것" 그 자체가 재미이자, 이 게임이 AI로 굴러가는 이유입니다.</em></p>

## 이 게임의 한 줄

**LLM을 빼면 게임이 성립하지 않습니다.** 손님의 대사·성격·힌트는 실시간 LLM이 연기하고,
채점은 결정적 코드가 담당합니다. "AI가 핵심 재미를 만드는가"라는 심사 기준을 정면으로 겨냥한 설계예요.

> 손님이 정답을 그냥 말해버리면 게임이 무너집니다. 그래서 **정답 누설 금지 규칙**을 프롬프트에 박아 두고,
> 시나리오 19개짜리 [회귀 테스트](.github/workflows/prompt-regression.yml)로 매 PR마다 지킵니다.

## 어떻게 노나

1. **손님 등장** — 괴물이 애매한 주문을 던진다.
2. **대화** — 채팅으로 질문해 원하는 맛·색·토핑·쪽지를 좁힌다. *(손님은 쉽게 정답을 말해주지 않는다.)*
3. **제작** — 6단계: 시트 반죽 → 케이크 베이스 → 생크림 → 토핑 → 데코 → 쪽지.
4. **확인 → 주기** — 완성본을 한 번 훑어보고 손님에게 건넨다.
5. **채점** — 손님 반응·별점·코인. 마음에 안 들면 **다시하기**.
6. 손님 **5명**을 모두 받으면 영업 종료 → 정산 → 엔딩.

### 규칙 요약

| | |
|---|---|
| 손님 | 5명 (첫 손님은 튜토리얼) |
| 통과선 | 60점 — 그 아래면 손님이 안 사간다(코인 0) |
| 별점 | 85 / 70 / 60 / 30점에서 ★5·4·3·2, 그 아래 ★1 |
| 배점 | 케이크 베이스 25 · 토핑 25 · 쪽지 20 · 시트 15 · 생크림 10 · 데코 10 |
| 대화 비용 | 질문 1턴당 −2점, 기본 10턴. 더 필요하면 코인으로 산다 |
| 엔딩 | 코인 **400** 이상이면 굿 엔딩 |

## 실행

```bash
npm install
npm run dev        # http://localhost:5173 — API 키 없이도 mock 대화로 끝까지 플레이 가능
```

실제 LLM(손님 대화)까지 로컬에서 켜려면 터미널 2개:

```bash
npm run api        # localhost:3001 — 서버리스 함수(chat/judge)
npm run dev        # localhost:5173 — 프론트
# 사전: .env.local 에 OPENAI_API_KEY 설정 (.env.example 참고)
```

```bash
npm test           # 채점 로직 단위 테스트
npm run build      # 프로덕션 빌드
```

## 기술 스택

- **프론트** — React 18 + Vite (순수 JS, TypeScript 미사용)
- **백엔드** — Vercel 서버리스 함수 (`/api`): 대화(`chat`)·판정(`judge`)
- **LLM** — OpenAI(기본 `gpt-4o-mini`) / Anthropic 전환 가능 — `api/_llm.js` 한 곳에서 추상화
- **사운드** — Howler.js (장면별 BGM + 효과음, 각각 따로 끌 수 있음)
- **배포** — Vercel(프로덕션) · GitHub Pages(정적) · Capacitor(APK)
- **아트** — 직접 그린 손그림을 PIL로 누끼·색틴트 처리한 webp

### 채점은 왜 코드가 하나

LLM은 **연기만** 하고, 점수는 `src/scoreCake.js`가 결정적으로 계산합니다.
같은 케이크는 언제나 같은 점수 — 모델이 후해지거나 박해지는 흔들림이 없습니다.

### APK는 왜 껍데기인가

Capacitor를 **remote 모드**(`server.url`)로 씁니다. 앱은 WebView 껍데기이고 내용은 배포된 웹을 띄웁니다.
덕분에 **웹을 고치면 설치된 앱도 같이 갱신**되고, APK를 다시 만들 필요가 없습니다.

## 프로젝트 구조

```
src/
  App.jsx            상태 머신 — 화면 전환·코인·별점·진행도를 여기서 관리
  screens/           TITLE·NAME·스토리·맵·대화·제작·확인·채점·정산·크레딧
  components/        CakeView(케이크 합성)·팔레트·HUD·설정 팝업 등
  data/              orders(주문·정답) · ingredients(재료·손님) · story(대사) · tutorial
  scoreCake.js       채점 — 배점·별점·코인·대화 비용 (단위 테스트 대상)
api/                 서버리스 함수 + 프롬프트(_monsterPrompt.js)
scripts/testChat.py  프롬프트 회귀 테스트 (CI에서 매 PR 실행)
```
