# 문서 디자인 규약

제출용 문서를 만들 때 따르는 규칙입니다. UI 컴포넌트 규약이 아니라 **PDF 문서 조판** 규약입니다.

## 왜 만들었나

제출물 세 개를 각자 만들다 보니 셋이 서로 다른 문서처럼 보이게 됐습니다. 같은 팀이 같은 날 낸 문서인데
잉크 색이 세 가지, 강조색은 있는 것과 없는 것이 섞였습니다.

| | 잉크 | 배경·보조 | 강조 | 제목 폰트 |
|---|---|---|---|---|
| `ai-tech-doc` | `#523412` 갈색 | 크림 `#F7EBD2` | 없음 | Pretendard |
| `game-guide` | `#4A3626` 갈색 | 크림 `#F6EFE3` | 탠 `#A3743F` | Pretendard 계열 |
| `team-roles` | `#1D1F20` 먹색 | 회색 `#F3F3F3` | 하늘 `#1FB0F0`, 주황 `#F2660B` | Barlow Condensed |

읽는 사람 입장에서는 셋이 한 팀 문서로 안 보입니다. 다음 문서부터는 아래를 기준선으로 씁니다.

기준선은 **웜 갈색·크림**입니다. 셋 중 둘이 이미 그 계열이고, 게임 아트가 색연필 파스텔이라 문서가
게임과 같은 온도를 갖습니다. `team-roles`의 모던 계열도 그 자체로는 완성도가 있지만 지금은 혼자
떨어져 있어, 다시 만들 일이 생기면 이쪽으로 맞춥니다.

## 색

원본은 `docs/ai-tech-doc.html` 의 `:root` 입니다. 값을 바꿀 일이 생기면 거기가 먼저입니다.

| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--ink` | `#523412` | 제목, 강조, 링크, 박스 왼쪽 바, 배지 바탕 |
| `--text` | `#1E1A16` | 본문 |
| `--muted` | `#8B8175` | 캡션, 부제, 표지 메타, 쪽번호 |
| `--cream` | `#F7EBD2` | 표 머리행, 코드 배경, 박스 배경 |
| `--line` | `#E4D7C4` | 표 구분선, 얇은 경계 |

여섯 번째 색은 두지 않습니다. 강조가 더 필요하면 색을 늘리지 말고 굵기나 여백으로 처리합니다.
색을 하나 더 쓰고 싶어질 때가 대개 위계가 안 잡힌 때입니다.

러닝 헤더는 `#B3A794`, 쪽번호는 `--muted` 를 씁니다. 둘 다 본문보다 확실히 흐려야 시선을 안 뺏습니다.

## 타이포그래피

폰트는 **Pretendard** 하나입니다. 없으면 Apple SD Gothic Neo, Malgun Gothic 순으로 떨어집니다.
코드는 SFMono, Menlo, Consolas 순.

기준 크기는 `10.4pt` 이고 나머지는 전부 `rem` 배수입니다. 절대값을 새로 쓰지 말고 배수를 쓰세요.

| | 크기 | 비고 |
|---|---|---|
| 표지 제목 | `3.1rem` | 자간 `-0.02em` |
| 장 제목 (h2) | `1.5rem` | 앞에 큰 숫자를 `#D9C9A8` 로 |
| 절 제목 (h3) | `1.12rem` | |
| 본문 | `1rem` = 10.4pt | 행간 `1.75` |
| 표 | `0.93rem` | 행간 `1.55` |
| 코드블록 | `0.79rem` | |
| 캡션·메타 | `0.82~0.9rem` | `--muted` |

한글 본문은 행간을 1.7 아래로 내리지 않습니다. 150% 밑으로 가면 받침이 많은 줄에서 답답해집니다.
`word-break: keep-all` 을 켜서 단어 중간에서 줄이 끊기지 않게 합니다.

제목 단계는 **세 단계까지**만 씁니다. h4가 필요하면 대개 절을 나눠야 할 때입니다.

숫자가 세로로 놓이는 곳(표, 지표)에는 `font-variant-numeric: tabular-nums` 를 겁니다.
자릿수가 안 맞으면 표가 지저분해 보입니다.

## 판형과 여백

A4 세로, 여백은 `17mm 18mm 14mm`. 좌우 18mm면 한글 본문이 한 줄에 45자 안팎으로 들어옵니다.

### 표지

1면을 통째로 씁니다. 위에서부터 배지, 제목, 한 줄 소개, 지표, 링크, 팀·날짜 순입니다.

- 배지 두 개: 대회명(잉크 바탕 흰 글씨)과 팀명(테두리만). 둘 다 `border-radius: 999px`.
- 지표는 네 칸을 넘기지 않습니다. 큰 숫자 위, 작은 설명 아래. 위아래 선으로 띠를 만듭니다.
- 링크는 문서마다 담당이 다릅니다. 게임 가이드가 플레이 링크·설치를 맡으므로 다른 문서는
  소스 저장소만 적고 나머지는 가이드를 가리킵니다. 같은 링크를 세 문서에 다 넣지 않습니다.

## 헤더와 푸터

쪽마다 반복되는 것과 문서 끝에 한 번 나오는 것을 구분합니다. 이름이 비슷해 헷갈리기 쉽습니다.

| | 어디에 | 몇 번 | 무엇을 |
|---|---|---|---|
| 러닝 헤더 | 쪽 위 여백 | 매 쪽 | 대회명(좌) · 현재 장(우) |
| 러닝 푸터 | 쪽 아래 여백 | 매 쪽 | 문서명·게임명(좌) · 쪽번호(우) |
| 문서 푸터 | 본문 맨 끝 | 한 번 | 팀·문서 버전·출처 주석 |

네 칸을 다 채웁니다. 여백에 넣는 글자는 본문보다 확실히 흐려야(`#B3A794` 안팎, 8pt) 시선을 안 뺏습니다.

### 매 쪽 반복되는 것

Chrome 131부터 `@page` 여백 상자와 `counter(page)` 를 지원해서 CSS만으로 됩니다.

```css
@page {
  size: A4; margin: 17mm 18mm 14mm;
  @top-left     { content: "NAN 2026 · NHN Game×AI 해커톤 사전과제"; font-size: 8pt; color: #B3A794; }
  @bottom-left  { content: "WeirdCakeZip 이상한 케이크 가게"; font-size: 8pt; color: #B3A794; }
  @bottom-right { content: counter(page) " / " counter(pages); font-size: 8.5pt; color: #8B8175; }
}
@page :first { @top-left { content: "" } @bottom-left { content: "" } @bottom-right { content: "" } }
```

**표지에는 아무것도 찍지 않습니다.** `:first` 로 비웁니다.

**현재 장 이름**은 `string()` 이 필요한데 Chrome이 지원하지 않습니다. 대신 **named page** 로 넣습니다.
장마다 `@page` 를 하나씩 만들고 그 장의 요소에 `page:` 를 겁니다.

```css
@page ch1 { @top-right { content: "01 게임 소개"; font-size: 8pt; color: #B3A794; } }
@page ch2 { @top-right { content: "02 게임 방법"; font-size: 8pt; color: #B3A794; } }
```
```html
<section class="ch1"> ... </section>   <!-- .ch1 { page: ch1 } -->
```

장이 여섯을 넘으면 관리가 번거로우니, 그때는 우상단을 **문서 이름 고정**으로 두는 편이 낫습니다.
장 이름이 없어도 쪽번호와 문서명이 있으면 길을 잃지 않습니다.

### 문서 끝 푸터

본문이 끝나는 자리에 한 번만 나옵니다. 위에 `--line` 한 줄을 긋고 `--muted` 로 작게 씁니다.
팀·게임명·문서 버전(날짜)을 적고, 인용한 원본이 있으면 그 출처를 한 줄 답니다.

이 푸터만 남고 쪽이 넘어가면 보기 나쁩니다. 여백을 조금 줄여 앞장으로 끌어올리세요.

## 요소별 규칙

**표.** 세로선을 긋지 않습니다. 행 아래 `--line` 한 줄만. 머리행은 `--cream` 바탕에 굵기 600.
셀 정렬은 위쪽(`vertical-align: top`), 숫자 열은 오른쪽 정렬.

**박스.** 왼쪽에 잉크색 4px 바, 크림 배경, 오른쪽만 둥글게(`0 10px 10px 0`). 제목 한 줄을 굵게 답니다.
장마다 하나둘이면 충분하고, 연달아 세 개가 나오면 본문으로 풀어야 할 내용입니다.

**코드.** 박스와 같은 모양이되 등폭 글꼴. 인라인 코드는 크림 배경에 `border-radius: 5px`.
명령어 안 공백은 `&nbsp;` 로 묶습니다. `npm run dev` 가 줄바꿈으로 쪼개지면 명령어로 안 읽힙니다.

**그림.** 테두리 `--line` 1px, 모서리 8px, 캡션은 그림 **아래** 가운데, `--muted`.
표 제목은 표 위, 그림 캡션은 그림 아래입니다. 섞지 마세요.

**장 번호.** h2 앞에 큰 숫자를 `#D9C9A8` 로 흐리게 둡니다. 마침표는 붙이지 않습니다.

## 인쇄 조판

화면과 달리 PDF는 쪽이 끊깁니다. 아래를 안 걸면 표가 두 쪽에 걸치고 제목만 쪽 끝에 남습니다.

```css
h2, h3        { break-after: avoid; }   /* 제목이 쪽 끝에 혼자 남지 않게 */
p             { break-inside: avoid; orphans: 2; widows: 2; }
table, pre    { break-inside: avoid; }
.box, figure  { break-inside: avoid; }
```

`break-inside: avoid` 를 걸면 그 요소가 통째로 다음 쪽으로 밀려 아래에 빈 공간이 생깁니다.
20mm 안팎은 정상입니다. 40mm 넘게 남으면 그 요소를 나누거나 앞 문단을 줄이세요.

다만 다이어그램이나 넓은 표처럼 **쪼갤 수 없는 블록**이면 그대로 둡니다. 두 쪽에 걸쳐 놓는 것보다
빈 공간이 낫습니다. `ai-tech-doc` 2쪽(구조 다이어그램)과 4쪽(검증 표)이 그 경우로, 각각 44mm씩
남지만 손대지 않았습니다. 빈 공간을 줄이려고 다이어그램을 자르면 읽을 수 없게 됩니다.

**마지막 장에 푸터만 남는 것**을 특히 조심하세요. 여백을 조금 줄여 앞장으로 끌어올리는 편이 낫습니다.

## 만들고 내보내기

HTML 한 파일로 쓰고 Chrome으로 PDF를 뽑습니다.

```bash
node -e '
const { chromium } = require("playwright-core");
(async () => {
  const b = await chromium.launch({ executablePath: "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" });
  const p = await b.newPage();
  await p.goto("file://" + process.argv[1], { waitUntil: "networkidle" });
  await p.pdf({ path: process.argv[2], printBackground: true, preferCSSPageSize: true });
  await b.close();
})();' "$PWD/docs/문서.html" "$PWD/docs/문서.pdf"
```

`preferCSSPageSize: true` 를 꼭 넘기세요. 이걸 빼면 `@page` 의 여백 상자(러닝 헤더·쪽번호)가 안 나옵니다.

**HTML을 저장소에 함께 둡니다.** PDF만 커밋하면 나중에 한 글자도 못 고칩니다. 실제로 `team-roles`는
PDF가 HTML보다 먼저 커밋돼 둘이 어긋났고, 고칠 때 원본을 다시 만들어야 했습니다.

## 낼 때 확인할 것

- [ ] 헤더·푸터 네 칸이 채워져 있고, 표지에는 아무것도 없다
- [ ] 색이 위 다섯 개 안에서만 쓰였다
- [ ] 제목 단계가 세 단계를 안 넘는다
- [ ] 표에 세로선이 없다
- [ ] 마지막 장이 푸터만으로 끝나지 않는다
- [ ] 빈 공간이 40mm 넘게 남는 쪽이 없다 (쪼갤 수 없는 블록 때문이면 예외)
- [ ] 다른 제출물과 겹치는 내용이 없다
- [ ] HTML 원본을 함께 커밋했다

## 글의 톤

- em dash(`—`)를 쓰지 않습니다. 한국어 문서에서 눈에 띄게 번역투로 읽힙니다. 쉼표나 마침표로 끊으세요.
- 굵게는 한 단락에 한두 군데까지입니다. 문장 전체를 굵게 하면 강조가 아니라 배경이 됩니다.
- 모든 항목을 `**이름** 설명` 같은 한 모양으로 늘어놓지 마세요. 몇 개는 평서문으로 풀어야 읽힙니다.
- 수치는 근거가 있는 것만 적습니다. 어디서 나온 숫자인지 한 줄로 밝힐 수 있어야 합니다.

## 지금 갈라져 있는 것

`team-roles` 가 먹색·회색 바탕에 하늘색·주황 강조, 제목은 Barlow Condensed 입니다. 이번 제출은
이대로 나가고, 다시 손볼 일이 생기면 위 기준선으로 맞춥니다. HTML 원본이 저장소에 없어서
지금 맞추려면 처음부터 다시 만들어야 합니다.

헤더·푸터도 갈라져 있습니다. `game-guide` 와 `team-roles` 는 네 칸을 다 쓰는데
(대회명 / 현재 장 / 문서명 / 쪽번호), `ai-tech-doc` 은 우측 두 칸만 씁니다.
위 기준선은 앞의 둘을 따랐습니다. 셋 중 둘이 이미 그렇게 하고 있고, 장이 여섯인 문서에서는
현재 장 표시가 실제로 길잡이가 됩니다.
