# 위키에 없는 결정·발견 정리 (3차 미팅 안건)

> 작성 2026-07-29 · **2026-08-01 갱신** (손그림 에셋 교체 반영) · 대상 회의 **3차 미팅 (2026-08-04)**
> H4(KAN-14) 목업 v2 작업 중에 나온 것들. 위키가 원본이므로 **회의에서 확정한 뒤 위키에 반영**한다.

## A. 위키를 고쳐야 하는 것 (기존 내용과 다름)

### A-1. 스테이지당 손님 4명 → **5명**

- 위키 [게임 플로우]는 "스테이지 3개 × 손님 4명 = 12판", 260725 회의록은 "손님 5명 정도"
- **5명이 맞음** (2026-07-29 확인). 위키가 미갱신
- 패치 준비됨: `docs/specs/wiki-stage-5customers.patch`
- ⚠️ 부수 효과: 3 × 5 = **15판**이면 한 판 1~2분 기준 **15~30분** → 위키에 적힌 목표 분량(10~15분)을 넘는다.
  줄여야 하면 손님 수가 아니라 **스테이지 수**를 건드리자고 문구에 적어뒀음 → **회의에서 확인**
- → 반영: 위키 `게임 플로우` / 손님 그림 수(S7)

### A-2. 제작 단계 표기 — "6단계"인데 나열은 7개

- 위키: "시트 반죽 → 굽기 → 색내기 → 생크림 → 토핑 → 데코 → 레터링" (7개인데 6단계라 씀)
- 결정: **굽기는 스텝이 아니라 연출**. 진행바는 **6칸**
  → ① 시트 반죽 ② 케이크 베이스 ③ 생크림 ④ 토핑 ⑤ 데코 ⑥ 쪽지
- 굽기는 시트 반죽 완료 후 자동 연출 (`bowl_dough` → `dough_knead` → `dough_*` → 완성 시트)
- 채점 항목 6개와도 수가 맞아 설명이 쉬워짐
- → 반영: 위키 `게임 플로우`, `게임 아키텍처`

## B. 새로 정한 것 (위키에 없음)

### B-1. 튜토리얼 제안 버블은 **무료**

- 스테이지 1에서 버블을 눌러 보낸 질문은 **턴 소모·감점 없음**
- 이유: 가르쳐준 대로 눌렀는데 −2점이면 튜토리얼이 아니게 된다
- UI에 `무료 · 턴 X` 배지로 일반 질문과 구분
- → 반영: 위키 `게임 플로우` 「대화 예산」에 예외 한 줄

### B-2. UI 디자인 방향 = **스티커 오버레이**

- 배경 그림 위에 **흰 채움 + 굵은 검정 아웃라인** UI를 스티커처럼 얹는다
- 규칙 4개
  1. 모든 UI 요소 = 흰 채움 + 잉크 아웃라인 **2.2px** (에셋 획 굵기와 동일)
  2. 강조는 색이 아니라 **반전**으로 (주 버튼·내 말풍선·완료 세그먼트만 잉크 채움)
  3. **UI는 색을 갖지 않는다.** 색은 에셋·재료에서만 (예외: 하트 핑크, 코인·별 노랑)
  4. 비활성은 회색이 아니라 **opacity 0.4**
- 이 방향을 고른 이유: 배경 그림이 미정이고 케이크 색이 플레이어마다 달라, UI가 색을 가지면 재료와 경쟁한다.
  **그림체가 색연필로 바뀌어도 이 구조는 유지된다**
- → 반영: 위키 `세계관·톤` 비주얼 방향, 또는 신규 「UI 스타일 가이드」 페이지

### B-3. 잉크색 = `#1A1A1A` (에셋 실측)

- v1 목업의 `#3A3530`(갈색기 검정) 폐기. 에셋 실제 아웃라인이 `#1A1A1A`라 나란히 놓으면 UI가 흐려 보였음
- 함께 확정한 값: 하트 `#F8C8D0` · 코인/별 `#F5D563` · 시트 크림 `#F7EBD2` · 보조 글자 `#8B8175`
- ⚠️ 이 색들은 **현재 에셋에서 뽑은 임시값**. 그림체 전환(S7) 후 재추출 필요
- → 반영: 신규 「UI 스타일 가이드」

### B-4. 배경색 토큰을 두지 않는다 + veil/dim 필수

- 배경은 그림이 담당하고 교체 예정이므로 `--bg` 같은 토큰을 만들지 않는다
- 대신 **흰 베일**(로딩 등 전체 화면)과 **딤**(팝업 뒤)을 표준 장치로 둔다
- 밤 배경에서 흰 아웃라인 요소가 묻히는 것을 막는 유일한 수단 → 생략 금지
- → 반영: 신규 「UI 스타일 가이드」

### B-5. 화면 목록 **15종** 확정

기존 목업(6종) + 신규 9종. 굵게 표시한 것이 신규.

| # | 화면 | # | 화면 |
|---|---|---|---|
| 01 | 타이틀 | 09 | 제작 6/6 쪽지 |
| 02 | **스테이지 맵** | 10 | **대화 팝업** |
| 03 | 주문·채팅(튜토) | 11 | **재료 언락 팝업** |
| 04 | **제작 1/6 시트 반죽** | 12 | 완성 확인 |

- → 반영: 위키 「목업 v2」 페이지 신설 (v1은 덮지 않고 나란히 — 위키 규약)

### B-6. 정산 화면은 `scoreCake`의 `parts`를 **그대로** 표시

- v1 목업은 시트/데코/쪽지 3줄이었으나, 실제 채점 항목은 6개
  (시트반죽 15 · 케이크 베이스 25 · 토핑 25 · 쪽지 20 · 생크림 10 · 데코 10)
- 임의로 줄이지 않는다. 점수 숫자는 계속 숨김 — 항목별로는 "완벽 / 아쉬움" 같은 상태만
- → 반영: 위키 `게임 플로우` 「통과 판정·별점」 보강

### B-7. 없는 이미지는 조용히 비운다

- `Img` 컴포넌트(`onerror` → 숨김). 깨진 아이콘·콘솔 404를 노출하지 않는다
- 경로 규칙 `/assets/{prefix}_{id}.webp` → **파일을 넣기만 하면 코드 수정 없이 자동 반영**
- 재료 칩 폴백 순서: `PNG → 이모지 → 빈칸`
- → 반영: 위키 `게임 아키텍처` 또는 「UI 스타일 가이드」

### B-8. 제작 화면 상단 바에 **몬스터 아이콘** 추가

- `[몬스터 얼굴][고정된 최초 주문][··· 대화 열기]` 3분할
- 회의록의 "대화창은 미니 아이콘(몬스터 얼굴)로 접혀 있다"를 그대로 구현한 것
- → 반영: 위키 「목업 v2」

### B-9. 제작 화면 하단 버튼 2종의 의미 구분

- **다시만들기** = 이 단계를 처음 상태로 / **되돌리기 ↺** = 마지막 동작 하나만 취소
- `↺`는 **여러 개를 쌓는 단계에만** 둔다 → 3/6 생크림, 4/6 토핑에만 있음
  (시트반죽·케이크 베이스·데코·쪽지는 토글/단일선택/개수조절/텍스트라 불필요)
- 생크림도 쪽지처럼 **"안 올림" 선택 시 맛 팔레트 비활성**(opacity 0.4)
- → 반영: 위키 「목업 v2」 또는 「UI 스타일 가이드」

### B-10. **UI 아이콘·테두리도 손그림 에셋으로** 그린다

- 근거: 손그림 옆의 CSS 도형은 티가 난다. 에셋 아웃라인은 손으로 그린 떨림이 있는데 CSS 원은 완벽한 곡선
- **셋으로 나눈다** — 전부 이미지로 하지 않는다
  1. **아이콘 16종은 에셋** (하트 찬/빈 · 코인 · 별 찬/빈 · 자물쇠 · ≡ · ··· · ↺ · ✕ · → · −/+ · 진행바 세그먼트 2 · 다시플레이)
  2. **테두리 4종만 에셋** (pill / 카드 / 말풍선 / 팝업) → CSS `border-image`로 늘림.
     ⚠️ **버튼을 통째로 이미지로 만들지 않는다** — 문구마다 폭이 달라 이미지가 무한히 늘어나고, 텍스트를 구우면 문구 변경·접근성이 막힌다
  3. 텍스트·레이아웃·베일/딤·비활성은 코드
- **형식은 SVG 권장** — 크기 자유 + 색 변경 가능(같은 하트를 핑크/회색). PNG면 상태별로 파일이 2배
- **그리는 타이밍은 S7(그림체 전환)과 묶는다.** 케이크는 색연필인데 아이콘은 깔끔한 톤이면 또 어긋남
- **프론트는 기다리지 않는다** — `<Icon name="heart" />` 컴포넌트로 감싸고 내부는 임시 도형.
  `ui_heart.svg` 가 들어오면 **코드 수정 0으로 교체**된다 (B-7과 같은 규칙)
- 상세 목록: `docs/specs/asset-usage.md` 「UI 아이콘·테두리도 에셋으로」
- → 반영: S7/KAN-10 범위에 추가 + 「UI 스타일 가이드」

## C. 보고 (결정 아님, 사실 공유)

### C-2. 주문이 4건뿐 → 스테이지 1(5명)을 못 채운다

### C-6. 유령(`ghost`)이 로스터에서 빠졌다

- **4층 모델이 유지된다**: frame(그릇) → asset(에셋) → ui(글자·버튼)

### C-9. 추가 질문 구매가 구현됐다 — 스펙과 다르다

위키 스펙은 **11–15턴, 코인 30/턴 정액, 15턴이 절대 상한**이다.
S8 구현은 다르다:

```js
export const EXTRA_TURN_BUNDLE = 3;
export const EXTRA_TURN_PRICES = [30, 50, 100, 200];
```

- **3턴 묶음을 4번까지** → 최대 22턴 (10 + 12). 총 380코인
- 가격이 정액이 아니라 **에스컬레이션**
- 산 질문은 감점 없음 (스펙과 동일)

에스컬레이션 자체는 합리적이다 — 정액이면 코인만 있으면 무한히 미룰 수 있는데,
살수록 비싸지면 "몇 번 더 물어볼까"가 매번 실제 판단이 된다.
한 판 최대 수익이 100코인이라 380코인은 실질 한계로도 작동한다.

- → 회의 안건 **D-15**
